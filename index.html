For someone about to put real data on a project that "has a login"

URL Family Check

You open the address you share with people. A login appears. That does not say what the project's other addresses do. Preview links, old deployment addresses, and the host's own pages.dev name can be a different door.

This page does not contact your project and does not store anything. The command below runs on your computer. It does not log in, and it does not follow a redirect.

Ask each address yourself

Copy every address your host lists for the project — the custom domain, the host's own project name, preview links, and older deployment links — not only the one you already tested. Then:

python3 check.py https://app.example.com https://older-deployment.example

Or one address per line in a text file: python3 check.py --file addresses.txt

You get one line per address:

verdictwhat came back
redirect301, 302, 303, 307, or 308 only, and the Location it named. Not followed. 304 is not a redirect. On Vercel, the login is this redirect, so a redirect is not an open page and not proof you saw a login.
challenged401. Something asked for credentials.
refused403. Refused, without serving a page.
served200–299. This address returned a page. The body is not read, so this is not a judgment of what the page says.
otherAny other HTTP status, a bad address, or the request failed. A failure is not "protected".

The command sends no cookie and no password. An address that contains a username or password is refused. At most 40 addresses.

What to paste, from each host's own docs

Read on 14 November 2026. These are the hosts' sentences about which addresses a setting covers. They are not a measurement of your project. Settings change; if you are reading this later, open the linked page before you trust a row.

Vercel

Source: Deployment Protection, page date 15 September 2026, and Vercel Authentication, both fetched 14 November 2026.

  • Standard Protection — "Protects all deployments except production domains." Turning it on restricts the production generated deployment URL. The API name on the authentication page is all_except_custom_domains.
  • All Deployments — "all URLs are protected, including your production domain example.com and generated URLs like my-project-1234.vercel.app." API name all.
  • (Legacy) Standard Protection — protects preview URLs and deployment URLs. "All up-to-date production URLs remain unprotected." API name prod_deployment_urls_and_all_previews.
  • (Legacy) Pre-Production Deployments — "Protects only preview URLs. Does not protect past production deployments." The same page says past or current generated production branch URLs like *-main.vercel.app remain accessible. API name preview.

The authentication page says visitors "encounter a Vercel login redirect," and that authentication "protects all your existing and future deployments in the environments you selected." So "we turned it on after that deploy" is not, on that page, an exception. The exception that page does name is the legacy scope above: production URLs, including older *-main.vercel.app addresses, stay open.

Netlify

Source: Password Protection overview, fetched 14 November 2026.

  • You choose "all site deploys" or "only Deploy Previews and branch deploys."
  • Protect all deploys includes production deploys, Deploy Previews, and branch deploys.
  • Protect only non-production deploys keeps production open and protects Deploy Previews and branch deploys. The page says this non-production-only option is for Enterprise plans in the older settings.
  • On credit-based plans the same choice is worded "Production and previews" or "Previews only."

That page talks about production deploys, Deploy Previews, and branch deploys. It does not, in the text read that day, name a further class of per-deploy link. Paste every address the deploys list shows anyway. The command is how you see what each one does.

Cloudflare Pages

Source: Preview deployments, fetched 14 November 2026.

  • "By default, these deployment URLs are public."
  • Enabling the preview access policy "will only protect your preview deployments (for example, 373f31e2.user-example.pages.dev and every other randomly generated preview link) and not your *.pages.dev domain or custom domain."
  • Access for the *.pages.dev domain and the custom domain, together with previews, is a separate setup. The page points at its known-issues section for that.

The addresses in that example are the documentation's, not a site this tool measured.

What this does not do

  • It does not list your project's addresses for you. The host's dashboard already lists deploys; this asks the ones you paste.
  • It does not log in, follow redirects, or decide that a 200 page is a login form. A form that returns 200 is served.
  • It is not a monitor. Run it when you change the setting or ship a deploy. Nothing here runs after that.
  • It does not scan addresses you did not type. Point it only at a project you operate.

Scope sentences read 14 November 2026 from the three pages linked above. The command's rules are the same in check.py.
